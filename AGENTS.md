# Working on project coordination

- Entry points: compiled `dist/src/cli.js` (source `src/cli.ts`) and `coordinate` in `src/agent.ts`. `npm ci` then `npm run build`; Node 22.13+ and an Anthropic key for normal model runs. `list`, `init`, help and all checks need no provider. SDK is pinned Mastra 1.77.0 with its bundled Anthropic adapter; do not add an unnecessary provider package or a scripted production mode.
- `coordinate` owns a fresh agent, run abort signal, private receipt and canonical-file claim. One run per file/process; aliases cannot bypass ownership. No cross-process lock exists. `buildCoordinator` is lower-level and caller-owned. SDK model caches/shared fetch remain library/caller resources; no private-cache reset or durable conversation memory is claimed.
- `src/completion.ts` must hold native response chunks until finish validation. An output processor alone failed the real max_tokens/tool regression because tools could execute eagerly. Preserve the actual router/HTTP tests. The pinned v2 router emits v3 unified/raw finish metadata; retain both. JSON generate is qualified; wire SSE is not.
- Disable both model and stability-processor retries: maxRetries=0, errorProcessorDefaults=false, maxProcessorRetries=0. Empty errorProcessors alone still merges defaults. Keep original SDK errors and causes. Normal limits are eight steps/4,096 output tokens, 30 seconds/model and 240 seconds/run. CLI signals and caller aborts reach the SDK fetch.
- Completion describes the provider loop, not task correctness. A handled tool error may precede a terminal answer. Inspect actual records/revisions, owner channel, prior work and action results; never infer success from final text. Earlier committed effects survive later failure. No automatic provider retry or rollback.
- `src/evidence.ts` publishes private atomic schema-1 receipts before execution, on model observations/tool results and on exit. Initial/final hashes identify exact state bytes. Original SDK-decoded provider JSON/error text is separate from normalized SDK usage; missing/partial/invalid/reported-zero counts and failed-attempt measurements remain distinct. Cost is unknown. One MiB capture is an SDK representation limit, not a wire-size guarantee. Keep credentials/config objects out of receipts.
- Errors expose observations/evidence/receiptPath, including persistent publication errors in memory. Persistence failures abort further work; do not report a file as durable if publication failed. Forced termination can leave a running receipt/staging file; inspect the actual workspace before resuming.
- Tools in `src/tools.ts` use only local `Workspace` operations. IDs are caller-owned/task-bound, not model arguments. Initial status changes require current safe-integer revisions; replays show current state and cannot undo later work. Changed task/payload needs a new ID. One create/post per request, one chosen status per issue/request.
- `src/workspace.ts` validates record shapes/unique IDs/relationships before reads and publication. Preserve imported ID gaps and safe-integer exhaustion checks. Atomic private file replacement includes business state and journals/audit together; it is not a multi-file or cross-process transaction. Preferred channels/history can remain when destinations become unavailable.
- `datasets/manifest.json` binds eight version-2 snapshots/four profiles to file hashes and identity. Busy has 18 issues/12 posts/ten prior human handoffs. Legacy `fixtures/` are immutable authoring inputs for `scripts/build-fixtures.mjs`; regenerate the owned cases with `npm run fixtures:build`. No model results/usage are seeded. Manifest expectations and scenario briefs must remain outside target context.
- Init is private/exclusive and checks exact file hash plus declared case identity; stop the owner and use a fresh file for independent cases. Original task/request IDs must match seeded partial/completed intents. State reset does not erase receipts, SDK caches or provider billing/retention.
- `npm run check` has 57 offline checks, including native CLI/SDK, storage failure, busy/recovery and data drift. `npm run check:package` builds a locked archive outside checkout and verifies its CLI/data/service behavior. It applies the existing guarded argparse repair after an ignore-scripts install; preserve parser compatibility tests and removal criteria in scripts/README.md.
- Pending-fetch test promises need an owned socket-equivalent ref'd handle because SDK deadline timers are unref'd. Clear it on abort/exit; keep this harness detail out of production. The CLI preload under tests is test-only and never imported by a normal run. Controlled choices are not live model judgment or measured billing.
- Fictional data only; no production account fallback, retired Firedrill API or invented platform client. Live provider/budget, released Firedrill contract and public visibility/license decisions remain parked.
