# Agent guide

The application entry point is `src/cli.ts`, which calls `src/agent.ts`. The Mastra agent is built with `@mastra/core/agent` and `createTool()` definitions in `src/tools.ts`. `src/workspace.ts` is the only state boundary.

- Requires Node.js 22.13+; install with `npm ci`, build with `npm run build`.
- Offline check: `npm run check`. This compiles the Mastra integration and tests cross-service state behavior without a model key.
- Normal read task: `npm run coordinate -- init --seed fixtures/starter-workspace.json --state run-output/workspace.json`; then set `ANTHROPIC_API_KEY` and run `npm run coordinate -- run --state run-output/workspace.json --task "Find the admin invite issue"`.
- Writes: add `--allow-writes` for an authorized synthetic issue update/create or channel post. The application owns retry IDs and binds each ID to the original task. Tool schemas accept no model-controlled IDs. A request can create one issue, choose one status per issue and post once; additional intent needs a new ID. No production account can be used as fallback.
- Model: `COORDINATOR_MODEL` or `--model`, in Mastra's `anthropic/<model>` format.
- State/reset: five fictional profiles declare dataset `synthetic-project-workspace`, version 1. Each case copies one to a fresh state path. State is shared across issue, repository and channel tools, with caller task bindings and status-update records. A path is sequential only, not safe for concurrent writers. Saves flush before atomic replacement and clean up staged files.
- Completion: after `agent.generate()`, the receipt includes `executionStatus` and `finishReason`. Only SDK stop plus a terminal answer is a completed execution; earlier progress cannot substitute for an empty final step. Bounded unfinished loops exit nonzero even if they emitted text. A completed loop is not proof of task correctness. Partial state survives errors and needs inspection before retrying.
- Replay: status replays must not increment revisions or undo later work. Return current state with `replayed: true`; it is not proof that the old requested status remains current. The read directory includes owner/channel mappings, and `readChannel` exposes up to 20 posts for recovery without inventing destinations.
- Evidence: terminal answer, earlier progress, actual state/audit entries, issue/post counts and reported per-step/aggregate usage. Mastra `usage` is last-step usage; use `totalUsage` for a complete measured aggregate and preserve unknowns. Never treat scripted SDK token values as live evidence. The 19-check suite includes actual Mastra loops, bound writes and incomplete-loop receipts without provider requests.
- Scope: narrow local operation subset, not vendor API compatibility. Keep credentials and private reports out of Git. Firedrill integration must wait for the new released contract.
